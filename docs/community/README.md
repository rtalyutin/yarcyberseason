# Команды, матчи, календарь и чат

Реализация пунктов 2–5 ТЗ. Регистрация сохранена в действующей Яндекс Форме. Аккаунтов, анкет, состава игроков, контактов и списка подписчиков нет.

## Где находятся данные

- `src/data/tournaments/*.json` — единственные канонические записи матчей и итогов турнира.
- `src/data/teams.json` — постоянные командные сущности и явные привязки названий к турнирам. После подтверждения организатором объединены записи из согласованной таблицы, включая «Синергия» / «Синергия ср»: 50 команд и 28 старых ID в `aliases`. Новые совпадения без подтверждения автоматически не объединяются.
- `src/data/community-config.json` — `soloRegistrationUrl` ведёт на предоставленную организатором Яндекс Форму регистрации соло-игроков. `teamSearchChatUrl` пока `null`: после получения ссылки на чат Telegram-канала появятся действия «Найти команду» и «Нужен игрок». Сайт только открывает внешние ссылки, данные регистрации у себя не хранит.
- `src/data/calendar-publications.json` — публичные неперсональные сведения о публикации событий, их UID и ревизиях. Это не данные подписчиков.
- `docs/community/migration.json` — исходные записи до миграции, присвоенные ID и основания преобразования. Не загружается в приложение.

Ни в один из этих файлов не добавлять персональные данные. Автоматическая проверка запрещает ряд персональных полей; названия, логотипы, пояснения и URL всё равно должны проходить содержательную проверку перед публикацией.

## Добавить команду или подтвердить её историю

1. Добавить в `teams` объект с постоянным уникальным `id` из строчных латинских букв, цифр и дефисов, публичным командным `name` и `disciplines`, содержащим дисциплину турнира. `logo` необязателен и должен указывать на неперсональный локальный ресурс.
2. Добавить в `bindings` явную связь `{ "tournamentId": "…", "sourceName": "…", "teamId": "…" }`.
3. Для следующего турнира существующей команды добавить новую привязку к прежнему ID только после подтверждения идентичности. При переименовании изменить `name`; исторические `sourceName` и названия в старых матчах сохранять. Подтверждённое другое имя можно добавить в `previousNames` как `{ "name": "…", "context": "область применимости" }`.
4. Не превращать «Без соперника», «Не заявленная команда» и обозначения победителя будущей игры в команды.

При объединении сохранять один существующий ID, направлять к нему все `bindings`, а удалённые ID записывать в `aliases` как `{ "id": "старый-id", "teamId": "основной-id" }`. Только прямые ссылки на существующую команду, без цепочек. Старые страницы показывают полную объединённую историю; календарные адреса продолжают работать. Ведомость подтверждённых объединений — `docs/community/team-merges.json`. Исторические названия в турнирных JSON сохраняются.

Страница `/teams/{teamId}` формируется автоматически, как и ссылки с таблиц, итогов и матчей. Призовое место берётся из `results.placements`, не из посева. Технические исходы отделены от спортивной статистики.

## Добавить или исправить матч

Матч остаётся внутри своего турнирного JSON, в `stage.matches` или `stage.rounds[].matches`.

- У каждой опубликованной встречи должен быть постоянный уникальный внутри турнира `id` из строчных латинских букв, цифр и дефисов. Перестановка записей, смена даты и счёта ID не меняют.
- `status`: `scheduled`, `live`, `completed`, `walkover`, `bye`, `postponed`, `cancelled`, `unknown`. Настенные часы не устанавливают live/completed.
- `scoreKind`: `series` — выигранные карты; `rounds` — раунды одной карты CS2 BO1; `technical` — техническое решение; `unknown` — смысл исходных чисел не установлен.
- `resultConfirmed`: `true` только для подтверждённого однозначного итогового результата. Запланированная встреча не получает результат 0:0.
- `resultIssue`: необязательное публичное пояснение противоречия источника. Для неизвестной семантики исходные числа показываются с пояснением, а карточка и статистика не создаются.
- `maps`: только опубликованные карты. Если их нет, не добавлять нули и предполагаемые названия. В текущем CS2 BO1 `score1/score2` относятся к раундам, производная серия — 1:0/0:1.
- `scheduledAt`: точный ISO-момент с часовым поясом, например `2026-10-10T15:00:00+03:00`. Пример синтетический, не расписание турнира. Поля `dateDisplay`, `date`, `time` сохраняют неполную исходную дату; неизвестные год/пояс не восстанавливаются из имени файла. Назначенная встреча с неполной датой видна на странице, но ещё не включается в календарь.
- `winnerTo` / `loserTo`: `{ "matchId": "…", "tournamentId": "…", "slot": 1 }`; `tournamentId` и `slot` необязательны. Ссылка задаётся по подтверждённой сетке; при отсутствии slot валидатор проверяет наличие нужного участника на любой стороне. Для текущего CS2 добавлены связи опубликованного double elimination; отсутствующая историческая сетка Dota не реконструируется.
- `broadcastUrl`, `vodUrl` (или существующий `replayUrl`), `highlights: [{ "title": "…", "url": "https://…" }]` — подтверждённые публичные HTTPS-ссылки, без персональных параметров. Автопоиска видео и загрузки стороннего плеера нет.

После изменения результата согласовать таблицы, участников следующих матчей, опубликованные итоги и пояснения. Валидатор обнаруживает противоречие серии картам/формату, победителя итогам и участников указанным связям сетки. Он не заменяет организатора и не вычисляет правила всех турнирных форматов. Исправлять зависимые поля одним изменением; не публиковать наполовину обновлённую сетку.

Страница `/tournaments/{tournamentSlug}/matches/{matchId}` и PNG используют общую нормализованную запись. Карточка скачивается в браузере, 1200×630, с логотипом, дисциплиной, участниками, серией, опубликованными картами, датой и ссылкой. Уже скачанные файлы автоматически обновиться не могут.

## Обновить календарь

1. Изменить расписание/статус/участников в турнирном JSON и при необходимости привязки команды.
2. Выполнить `npm run calendar:sync`.
3. Просмотреть изменения `calendar-publications.json` и включить их в тот же коммит, что расписание.
4. Выполнить сборку и тесты.

`npm run build` генерирует `/calendars/teams/{teamId}.ics` для каждой заведённой команды и блокируется, если неперсональный реестр календарных публикаций отстал от расписания. После удаления/отмены ранее опубликованный UID остаётся в отменённой записи. Смена участника отменяет событие в старом календаре и публикует его в новом. При временно неизвестной дате прежнее время остаётся только в отменённой записи. Завершённые опубликованные события сохраняются.

Ссылки внутри ICS используют существующий публичный адрес `https://ycs.bar`; при переносе основного домена изменить origin в `scripts/community-build.mjs`. Endpoint раздаётся как `text/calendar`, переоценивает кэш, разрешает GET/HEAD и не подменяет отсутствующий календарь HTML.

Сайт не хранит подписчиков. Частоту обновления определяет календарное приложение. Импорт одного скачанного файла не равен подписке. Сейчас в исходниках нет будущих встреч с подтверждённым точным временем и поясом, поэтому 78 существующих лент валидны и пусты.

## Известное противоречие источника

`dota2-main-2026 / dota-main-group-16`: Самозванцы — Yellow Submarine, исходный счёт 1:1 при BO3. Числа и формат сохранены, статус помечен `unknown`, результат не участвует в новой статистике и не получает карточку. После уточнения организатором исправить данные и убрать `resultIssue`.

## Проверка и передача

```sh
npm run build
npm run test:sites
npm run test:matchday
npm run test:tournament
npm run test:community
```

`test:community` проверяет сохранение исходных значений, различение серии/раундов/технических решений, идентичность, неполное время, переносы/отмены/смену участника, защиту календарного формата и отрисовку всех 50 командных, 28 прежних командных адресов и 120 матчевых страниц без HTTP-сервера. Это не тест реального браузера.

Перед выпуском проверить мобильный и настольный интерфейс, фактическое скачивание PNG и подписку в календарных клиентах. Настройки инфраструктурных логов здесь не изменялись и не проверялись. Локальная реализация и тесты не означают отправку в main или обновление рабочего сайта.

## Регистрация Dota, 9 сентября 2026

Реестр schemaVersion 2 использует `disciplines` вместо `discipline`. Восемь новых карточек и восемь существующих связаны с 16 заявками через `participants` и `bindings`. `participants` задаёт имена, порядок и статус «Заявлена», а не посев. История и статистика разделены по дисциплине турнира. Составы не хранятся и не наследуются между дисциплинами. Соло-регистрация остаётся отдельным нерешённым вопросом. Внешняя командная форма требует входа владельца; её закрытие не выполнено изменением сайта.
