## Что переиспользовано

| Данные | Каноническое место |
|---|---|
| Команды, прежние ID, названия в турнирах | `src/data/teams.json` |
| Участники, расписание, серии, карты, таблицы, итоги | `src/data/tournaments/*.json` |
| Публичные составы и источники | `src/data/team-rosters.json` |
| Происхождение перенесённого набора | `src/data/data-sources.json` |

Последний файл содержит только метаданные происхождения, не копию данных.
`recorded` означает «перенесено из указанной версии репозитория»; это не новая
независимая проверка результата. Источники исходных составов сохранены отдельно.
Поля `resultConfirmed`, `status`, `resultIssue` матчей сохраняют прежний смысл.
При последующих фактических изменениях обновлять происхождение затронутой записи:
`provenance: {sourceUrl, status, observedAt}` в матче либо запись файла в manifest.
Для новых турнирных файлов запись в manifest обязательна.

## Подготовленная реализация

- В сериях сохранены прежние названия и добавлены постоянные `team1Id`/`team2Id`.
  Для неизвестного/технического соперника ID равен `null`. Валидатор сверяет ID
  с ранее утверждёнными привязками; новые команды автоматически не объединяются.
- Опубликованным картам добавлены постоянные `id`; BO1 со счётом раундов использует
  `mapId` той же записи. Неизвестные карты не создаются. Dota-ссылки сохраняют
  исходный внешний `matchId`. После назначения ID не пересчитывать по позиции!
- `community.maps` даёт индекс карт с `seriesKey` и ID команд из тех же JSON.
  Это вычисляемый индекс в памяти, а не второе хранилище результатов.
- Составы остаются снимками пары `tournamentId/teamId`, дисциплина определяется
  турниром. Отсутствие снимка означает `roster=null`, `rosterStatus=unknown`.
  Архивный опубликованный состав имеет статус `published`, не автоматически
  подтверждённую явку. `rosterCollection` фиксирует ожидание новых данных.
- Сборка блокируется при нарушениях ссылок/ID, дублях карт и внешних матчей,
  циклах сетки, неправильных датах и служебных полях. Скрытие матча не позволяет
  обойти проверки ID, статуса, даты, слота и связей сетки.
- Импорт публичного архива составов сначала проверяет схему и все ссылки.
  Совпавшая запись ничего не меняет. Конфликт требует отдельного рассмотрения,
  не перезаписывает прежнюю версию. История правок остаётся в git.

```sh
npm run data:check
npm run data:import-rosters -- /absolute/path/public-rosters.json
# Только после просмотра результата — запись локального файла:
npm run data:import-rosters -- /absolute/path/public-rosters.json --write
npm run test:data
```

Файл импорта — тот же разрешённый публичный формат `schemaVersion/sources/records`.
Не подавать сюда анкеты, контакты, документы и закрытые игровые аккаунты.
Повторный импорт не пишет файл, если набор не изменился. Исправление результата
и зависимых таблиц/сетки остаётся отдельной согласованной операцией.
