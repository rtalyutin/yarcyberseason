## Объект и границы

Ветка `codex/captain-cabinet-service`, базовый commit `d790ab11ae0e3a79185641ac52d16f181791575e` с незакоммиченными изменениями contract-5. Ниже зафиксирован манифест проверенных исходников. Linux, Node.js v24.19.0.

Использованы синтетические капитаны, Ed25519/AES-ключи, локальный HTTP и настоящий сервис. S3 SDK transport заменён имитацией, сохраняющей фактические зашифрованные PUT и проверяющей CAS. Текущий envelope независимо расшифрован через Node crypto с согласованным AAD. Реальных ключей, аккаунтов, S3-записей, Bot API или публикации не было.

QA04 использует управляемую историю: оба конкурента читают revision 6; победитель фиксирует 7; вторая запись с ETag 6 получает конфликт и повторно проверяет scheduleVersion. QA12 удерживает конкретный PUT до окончания cleanup, а QA17 запускает cleanup после фактического PUT и до ответа транспорта. Это воспроизводимые различители, не общий стресс-тест и не доказательство отсутствия всех возможных гонок.

Первый прогон дал 16/17: **ORACLE_FAIL**, а не дефект приложения. Проба ожидала отдельный `chat_opened` рядом с `message`, хотя чат открылся внутри транзакции согласования. Необязательный минимум числа событий убран; финальная проверка по-прежнему требует наличие `message` и отсутствие всех фактически существовавших chat events, их id и fingerprints после очистки.

Chromium в прежней попытке отсутствовал, скачивание вернуло HTML вместо архива; Cloud Browser не видел localhost. В этом проходе установка, tunnels и deployment не повторялись. Фактические mobile/wide клики, disable compose, очистка React-черновика и Telegram WebView пока не подтверждены. Проверка чистых функций QA15 не заменяет эту приёмку.

## Что означает удаление

Проверка доказывает отсутствие переписки и её служебных записей **в текущем объекте S3**, который записывает код. Наличие старых версий объектов, Object Lock, резервных копий и фактическую политику хранения этого bucket в данном окружении проверить нельзя. Удаление всех инфраструктурных копий не заявляется; перед выпуском это отдельный gate конфигурации хранения. Также не проверены настоящие Telegram Serverless, серверные секреты, S3 CAS и опубликованная конфигурация фонового worker.
