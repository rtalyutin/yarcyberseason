## Поведение

- «Итоги» добавлены в навигацию и экран турнира только при наличии валидного объекта `results` выбранного турнира. На реальных текущих данных этот объект отсутствует; раздел скрыт, прямой `?section=results` и launch-target нормализуются к обзору. Исходное действие `#results` адаптируется тем же правилом.
- Места берутся из `results.placements`, упорядочены по опубликованному номеру без мутации исходника. Частичный список сохраняет свои номера; отсутствующие места, призовые и победители не вычисляются.
- Если валидный объект содержит только `finalMatchId`, финал показывается вместе с пояснением «Итоговые места ещё не опубликованы».
- Карточка финала выбирает существующий MatchViewModel по ID и использует общий MatchRow: нормализованный счёт, единица счёта, статус, дата, раскрытие опубликованных карт и внешних материалов. Это тот же результат, что в Матчах и Плей-офф. Технический финал не изображает сыгранные карты.
- Минимальное визуальное продолжение существующего дизайна: адаптивные карточки мест, текущие токены, красный акцент первого места, перенос длинных названий. Нативная карточка финала сохраняет действующее раскрытие и фокус.
- Усилена только локальная проверка source results: опубликованная команда должна разрешаться в выбранном турнире; одна team identity не может занимать несколько мест; первое и второе места согласованы с подтверждённым финалом, его участники не могут быть записаны ниже. Существующие проверки скрытого/отсутствующего/неподтверждённого финала и повторяющихся номеров сохранены. Недостоверный объект блокирует построение модели.
